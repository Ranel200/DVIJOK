# План готовности backend для admin frontend

План составлен по фактическому frontend `Ranel200/DVIJOK` и текущим роутерам
backend. Frontend в ходе реализации не изменялся.

| Этап | Результат | Статус |
|---|---|---|
| 1. Auth и CRM-основа | JSON/form login, frontend registration facade, источник заказа, вложенные клиент/авто | Готово |
| 2. Календарь | Недельная проекция, индивидуальный график, availability, явная бронь без автоподстановки | Готово |
| 3. Сотрудники | Единая User/Mechanic-карточка и совместимые `/schedule/employees` | Готово |
| 4. Услуги | Типы цены, мастера, Excel, summary и плоский admin facade | Готово |
| 5. CRM | Канбан, список, создание/редактирование/статус/удаление, скидки строк | Готово |
| 6. Задачи | Персональные/общие задачи, статусы, summary, CRUD/bulk delete | Готово |
| 7. Настройки | Профиль организации, подписка, безопасная смена пароля | Готово |
| 8. QR и документы | Постоянный referral URL/SVG, HTML/PDF заказ-наряда | Готово в backend |
| 9. Миграции и тесты | Единая forward Alembic-цепочка, PostgreSQL drift check, тесты | Готово |
| 10. Подключение frontend | Переключить mock API, добавить вызовы для локальных UI-операций и QR | Нужное изменение frontend описано; ожидает разрешения |

## Принятые правила

- Дата/время из новой CRM-формы не резервирует календарь. Backend предлагает
  свободные слоты, пользователь выбирает один, затем UI явно вызывает
  `/orders/{id}/reservation`.
- Один мастер не получает пересекающиеся брони. PostgreSQL-блокировка мастера
  сериализует конкурентные check+insert.
- Рабочие интервалы хранятся в `Europe/Moscow` (настраивается), weekday backend:
  `0=Пн`; frontend adapter переводит JS `0=Вс`.
- Повторяющиеся перерывы исключаются из availability и бронирования;
  датированные болезни/отпуска задаются blocks.
- Скидка позиции 0–100% сохраняется как snapshot и входит в итог заказа.
- Закрытие заказа требует оформленного документа.
- UI permissions влияют только на видимость меню; серверные права определяет
  role.
- «Удаление» сотрудника — деактивация, чтобы не разрушать историю.
- Пароли/хэши никогда не выдаются frontend.
