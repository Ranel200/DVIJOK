# Авторизация клиента звонком через SMS.ru

## Пользовательский сценарий

Frontend уже реализует нужный flow и визуально не меняется:

1. Клиент вводит российский номер телефона.
2. Frontend вызывает `POST /api/v1/client-auth/otp/request`.
3. SMS.ru звонит клиенту со случайного номера. Отвечать на звонок не нужно.
4. Клиент вводит последние четыре цифры входящего номера.
5. Frontend вызывает `POST /api/v1/client-auth/otp/verify`.
6. После успешной проверки backend создаёт или находит глобальный
   `ClientAccount` и выдаёт обычную access/refresh-сессию.

По документации SMS.ru Code Call запрос выполняется через
`POST https://sms.ru/code/call` с `phone`, IP пользователя и закрытым `api_id`.
Ответ содержит четырёхзначный `code`; backend сохраняет только его хэш с TTL и
никогда не отдаёт реальный код frontend.

## API

### `POST /api/v1/client-auth/otp/request`

Публичный endpoint с rate limit.

```json
{
  "phone": "+7 (999) 123-45-67"
}
```

Успешный ответ в режиме SMS.ru:

```json
{
  "detail": "Звонок поступит в ближайшее время. Введите последние 4 цифры номера.",
  "debug_code": null
}
```

Возможные ошибки:

- `422` — номер не прошёл валидацию;
- `429` — превышен лимит по номеру, IP или общий аварийный лимит расходов;
- `503` — SMS.ru недоступен, ключ не настроен либо провайдер отклонил звонок.

### `POST /api/v1/client-auth/otp/verify`

```json
{
  "phone": "+79991234567",
  "code": "4821",
  "full_name": "Иван Петров"
}
```

`code` — последние четыре цифры номера, с которого поступил звонок. При успехе
возвращается прежний совместимый `TokenPair`; при неверном или истёкшем коде —
`401`.

## Настройки backend

```dotenv
OTP_PROVIDER=sms_ru_call
SMS_RU_API_ID=<секретный API-ключ>
SMS_RU_CALL_URL=https://sms.ru/code/call
SMS_RU_TIMEOUT_SECONDS=10

OTP_CODE_TTL_SECONDS=300
OTP_MAX_ATTEMPTS=5
OTP_RATE_LIMIT_ATTEMPTS=5
OTP_RATE_LIMIT_WINDOW_SECONDS=3600
OTP_IP_RATE_LIMIT_ATTEMPTS=10
OTP_IP_RATE_LIMIT_WINDOW_SECONDS=3600
```

`SMS_RU_API_ID` хранится только в backend environment. Его нельзя помещать во
frontend, документацию с реальным значением или Git.

Глобального суточного лимита звонков нет. Защита от спама действует отдельно по
номеру телефона и IP согласно `OTP_RATE_LIMIT_*` и `OTP_IP_RATE_LIMIT_*`.
Лимиты сейчас in-memory, как и OTP store. Перед горизонтальным масштабированием
их необходимо перенести в Redis или продублировать на API gateway, иначе каждый
процесс будет считать свой лимит отдельно.

Для бесплатной локальной разработки используется `OTP_PROVIDER=local`. Только
в этом режиме и только при `DEBUG=true` endpoint может вернуть `debug_code`.

## Проверка без расходов

Автотесты подменяют HTTP-транспорт SMS.ru и проверяют:

- передачу нормализованного номера, IP и ключа;
- использование кода, полученного от провайдера;
- отсутствие кода в HTTP-ответе;
- вход по последним четырём цифрам;
- отсутствие общего лимита, блокирующего разных пользователей.

Ни один автоматический тест не обращается к настоящему SMS.ru API.
